## What the session covered

- **Stages in Development:** What each stage must prove before funding increases
- **Types of Prototypes:** Learning objective before fidelity or polish
- **MVP Versus Prototype:** What becomes real only with real users and cost
- **Types of MVPs:** Staged automation: what can be faked safely
- **AI Illusion Techniques:** When staged automation becomes deceptive
- **Governance Artifacts:** Keeping development honest

## Key ideas and cases

### Ideas that stayed with me

- **Name the learning goal first:** Each build step should state what it must prove before the team starts building.
- **Prototype ≠ MVP:** A prototype tests an idea cheaply; an MVP must deliver enough value that real users change behaviour.
- **Faking has limits:** Wizard-of-Oz and concierge MVPs speed learning, but create false trust if the illusion cannot be automated.

### Cases that made it concrete

- **Notion AI:** Moved from concept to broad use in staged steps tied to evidence.
- **Chatbot mockups:** Conversation prototypes test the experience before any model exists.
- **Wizard-of-Oz assistants:** Humans behind the curtain reveal demand before automation is built.
- **Go/no-go memos:** Governance artifacts make the next investment decision sharper.

## How my thinking shifted

| Before this session | After this session |
| --- | --- |
| Any early release is an MVP | An MVP must prove a specific behaviour change |
| Fidelity shows progress | The cheapest prototype that answers the question is best |
| Manual back-ends are a shortcut | Manual back-ends need an honest automation path |

## Applying it to my work

- **Concierge-test merchant lending:** Run a manual underwriting pilot before automating credit decisions.
- **Prototype brief template:** State the uncertainty, audience and success signal for every prototype.
- **Stage-gate funding:** Tie each increase in budget to a proven milestone, not to the calendar.

## Key takeaway

> Development discipline comes from making the learning objective explicit before the team starts building.

## Question I am still exploring

Where is the line between a legitimate Wizard-of-Oz test and misleading customers?
