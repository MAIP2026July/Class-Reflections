# Class 3 Reflection

## Session 3: AI Product Strategy and Opportunity Identification

### 1. From Problem to Strategy

The session outlined the following sequence for identifying and shaping
an AI product opportunity:

**Problem → AI opportunity → Feasibility → Value → Strategy**

An AI opportunity should be assessed in terms of both AI feasibility and
business value.

### 2. Opportunity Matrix

The opportunity matrix helps determine which opportunities to avoid,
investigate, or prioritise.

  -----------------------------------------------------------------------
  Business value          Low AI feasibility      High AI feasibility
  ----------------------- ----------------------- -----------------------
  **Low value**           Avoid                   Possible quick win

  **High value**          Avoid / develop a       Priority opportunity
                          strategy and            
                          investigate             
  -----------------------------------------------------------------------

The most attractive opportunity is one with both high business value and
high AI feasibility.

### 3. Factors That Determine AI Feasibility

AI feasibility is determined by considering:

-   Data
-   Technology
-   Integration
-   Skills
-   Cost
-   Time

These factors help assess whether an AI opportunity can realistically be
implemented.

## Session 3B: Build vs. Buy vs. API

### 4. Choosing an Implementation Approach

-   **Build:** Develop your own model.
-   **Buy:** Purchase or use an existing model.
-   **API:** Access a model through an API.

### 5. AI Feature vs. AI Platform

-   **AI feature:** An AI capability that improves an existing product.
-   **AI platform:** A reusable foundation that supports multiple
    products or use cases.

### 6. Jobs To Be Done (JTBD) Structure

The Jobs To Be Done framework expresses a user's need in this format:

> When \[situation\], I want to \[motivation\], so that \[desired
> outcome\].

This helps connect an AI opportunity to the user's actual situation,
motivation, and desired outcome.

### 7. What Makes a Good Strategy?

The notes highlight that a good strategy should be:

-   Relevant
-   Evidence-backed
-   Unromantic about hype

A strategy should be grounded in evidence rather than excitement about
AI alone.

### 8. Opportunity-to-Product Decision Flow

The session's example flow connects the opportunity to the
implementation decision:

**AI opportunity → User / Job → Feasibility → Value → Risk → Build / Buy
/ API → Feature / Platform**

This sequence helps evaluate the user need, practical feasibility,
business value, and risk before choosing an implementation approach and
deciding whether the outcome should be an AI feature or a reusable
platform.

### Reflection

A strong AI product strategy starts with a real problem and a clearly
understood user job. The opportunity must be evaluated for feasibility,
business value, and risk before deciding how to implement it. The Build,
Buy, or API decision should follow this assessment, along with the
choice between delivering an AI feature and creating a reusable AI
platform.
