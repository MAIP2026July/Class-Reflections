# Class 5 Reflection

**Date:** 29 August 2026  
**Topic:** AI opportunities, build buy API decisions and uncertain UX

The line I kept thinking about after this class was that customers do not pay extra simply because a product uses AI. The technology has to improve something they care about. It should save time, reduce cost, improve quality or make a previously difficult task possible. Otherwise, “AI-powered” is only a label.

The build, buy or API decision also felt less straightforward after the discussion. Building gives control but creates a long-term maintenance burden. Buying is faster but can make the product dependent on a vendor. An API looks flexible, but pricing, availability and model behaviour can still change. We may not need to own the model, but we do need to own the customer problem and the way we evaluate the result.

The UX part was especially relevant to Wayfinder AI. A disclaimer saying that AI can make mistakes is not enough. Workers need citations and a clear indication of what the system knows. If the source does not support an answer, the product should say so and create a route for escalation.

That failure can actually become useful feedback: the unanswered question shows the content team exactly what knowledge needs attention next.
