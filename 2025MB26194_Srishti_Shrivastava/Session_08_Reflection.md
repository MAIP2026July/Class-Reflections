# Class 8 Reflection

**Date:** 3 October 2026  
**Topic:** AI instability, prototypes, MVPs and decision gates

The example that stayed with me was how an AI can convert a temporary testing instruction into a permanent product rule. The generated specification may look professional, so the change can pass unnoticed. This creates a strange problem for the product manager: AI makes it easy to produce more material, but someone still has to read it carefully enough to catch what changed.

I had also been using prototype, MVP and pilot almost as interchangeable words. The class made their purposes clearer. A prototype helps us learn whether an idea or interaction can work. An MVP must provide real value to a real user. A pilot checks whether the product can operate in a limited real environment, including adoption and support.

For Wayfinder AI, a chatbot answering from a few sample SOPs would still be a prototype. An MVP would also need content approval, citations, abstention and a feedback path. A pilot would place that workflow at one site with actual workers and content owners.

This distinction matters because calling a demo an MVP creates false confidence. The name should reflect what has actually been tested, not how mature we want the product to sound.
