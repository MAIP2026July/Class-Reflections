# Session 13 Reflection

**Date:** 14 November 2026

This was the first presentation day, and the professor treated every presentation like a pitch to investors. One rule was that feedback to any team applies to all of us, so each point should be logged as a GitHub issue in our own repo and closed with a comment if it doesn't apply. I found that a sensible way to make sure nothing was lost.

The feedback I need to act on for AdmitAssist: swimlanes should show every role, mark AI steps as AI1, AI2 and so on, and show where a human checks the output. I need to say clearly who pays for the API calls, the school or me. The startup's business plan and the customer's return on investment are two separate calculations, and many teams, including promising ones, mixed them. A customer usually shares about 18 to 25% of the value created, so the school would expect savings of roughly three to four times the price. A pilot doesn't have to end in a plain yes or no; a conditional go is also a valid outcome. And something built for one organisation is a project, not a product. Using the Idea Hub team's tool to review all submissions without customising it per team was a good live example of that. My own gap is clear: I can estimate token and hosting costs, but I'm much weaker at showing the customer's ROI in a convincing way.
